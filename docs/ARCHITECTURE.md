# Архитектура парсера

## Что это

Многосайтовый парсер на Python, который собирает данные с HTML-страниц
и сохраняет в JSON + CSV.

**Ключевая идея:** код — движок, конфиг — задача.
Для нового сайта не нужно менять код — только YAML-конфиг.

## Общая схема
```
┌─────────────────────────────────────────────────────────────┐  
│ main.py (CLI)                                               │  
│ argparse: --site / --sites / --all                          │  
└─────────────────────────────────────────────────────────────┘  
                       ↓  
┌─────────────────────────────────────────────────────────────┐  
│ process_site()                                              │  
│ Оркестрация: fetch → extract → export                       │  
└─────────────────────────────────────────────────────────────┘  
                       ↓  
┌──────────────────────┼──────────────────────┐  
↓                      ↓                      ↓  
┌──────────┐ ┌──────────┐ ┌──────────┐  
│ fetcher  │ │extractor │ │ exporter │  
│ .py      │ │ .py      │ │ .py      │  
└──────────┘ └──────────┘ └──────────┘  
↓                  ↓           ↓  
HTML-код Данные (dict) JSON + CSV
```
## Модули

### `core/fetcher.py` — загрузка HTML

**Задача:** скачать HTML-страницу с вежливой паузой.

**Вход:** `url`, `user_agent`, `delay`
**Выход:** HTML-строка
**Ошибки:** логирует и пробрасывает `HTTPError`, `RequestException`

### `core/config_loader.py` — загрузка YAML

**Задача:** прочитать `sites/{site}.yaml` и проверить обязательные поля.

**Вход:** `site_name`
**Выход:** словарь с настройками
**Ошибки:** `FileNotFoundError`, `ValueError` (если поля нет)

**Обязательные поля:** `name`, `base_url`, `list_selector`, `fields`

### `core/extractor.py` — извлечение данных

**Задача:** применить селекторы из конфига к HTML.

**Вход:** HTML-элемент, конфиг полей
**Выход:** словарь `{field_name: value}`

**Типы полей:**
- `text` — берёт текст внутри тега
- `attribute` — берёт значение атрибута (`href`, `datetime`)

**Обработка:** если поле не найдено — `warning` + пустая строка, парсер продолжает.

### `core/exporter.py` — сохранение

**Задача:** сохранить данные в JSON и CSV.

**Вход:** список словарей, `site_name`, `output_dir`
**Выход:** пути к файлам

**Особенность:** в CSV списки превращаются в строки через `", ".join(...)`.

### `main.py` — оркестратор

**Задача:** собрать всё вместе + CLI.

**Аргументы:**
- `--site habr` — один сайт
- `--sites habr,rbc` — несколько
- `--all` — все из `sites/`

**Логика:** загружает конфиг → fetch → extract → export, обрабатывает ошибки, продолжает при падении одного сайта.

## Поток данных (пошагово)

Пример: `python main.py --site habr`
```
1. main.py  
    └── argparse читает аргумент --site habr  
    └── sites = ["habr"]
    
2. process_site("habr")  
    └── config_loader.load_site_config("habr")  
    └── читает sites/habr.yaml  
    └── проверяет обязательные поля  
    └── возвращает config
    
3. fetcher.fetch_page(config["base_url"], user_agent, delay)  
    └── requests.get(...)  
    └── time.sleep(delay)  
    └── возвращает HTML-строку
    
4. extractor.extract_all(html, config["list_selector"], config["fields"])  
    └── BeautifulSoup(html)  
    └── soup.select(list_selector) → список элементов  
    └── для каждого элемента → extract_fields()  
    └── возвращает список словарей
    
5. exporter.export_all(data, "habr")  
    └── save_json() → output/habr.json  
    └── save_csv() → output/habr.csv
    
6. main.py  
    └── логирует итог: 1/1 сайтов обработано
```

## Как добавить новый сайт

**Три шага:**

### Шаг 1: Разведка HTML

```bash
python tools/explore.py https://новый-сайт.com/ --delay 2
```
Инструмент покажет:

- Какие теги есть на странице
    
- Возможные контейнеры (сортировка по размеру)
### Шаг 2: Создать YAML
```bash
cp sites/habr.yaml sites/новый-сайт.yaml
nano sites/новый-сайт.yaml
```
Меняешь:

- `name`
    
- `base_url`
    
- `request_delay` (проверь `robots.txt`)
    
- `list_selector`
    
- `fields` (селекторы)
### Шаг 3: Тест
```bash
python main.py --site новый-сайт
```

**Код НЕ трогаем.** Только YAML.

### Что можно добавить

|Фича|Где менять|
|---|---|
|**Новый формат вывода** (XML, YAML)|`core/exporter.py`|
|**Новый тип поля** (`html`, `list`)|`core/extractor.py`|
|**Пагинация** (следующие страницы)|`core/crawler.py` (новый модуль)|
|**Детали статьи** (2-й уровень парсинга)|`core/crawler.py` (новый модуль)|
|**Новый CLI-аргумент**|`main.py`|
## Технологии

| Технология               | Где используется             | Зачем                 |
| ------------------------ | ---------------------------- | --------------------- |
| **Python 3.12**          | Везде                        | Основной язык         |
| **requests**             | `fetcher.py`                 | HTTP-запросы          |
| **BeautifulSoup + lxml** | `extractor.py`, `explore.py` | Парсинг HTML          |
| **PyYAML**               | `config_loader.py`           | Чтение YAML-конфигов  |
| **argparse**             | `main.py`, `explore.py`      | CLI-аргументы         |
| **logging**              | Все модули                   | Логи в консоль + файл |
| **csv, json**            | `exporter.py`                | Сохранение данных     |

## Ограничения

**Что парсер НЕ делает (пока):**

| Ограничение              | Почему                    | Когда добавим           |
| ------------------------ | ------------------------- | ----------------------- |
| **JavaScript-сайты**     | Нужен Selenium/Playwright | Проект 2.7              |
| **Пагинация**            | Только первая страница    | После 2.7               |
| **2-й уровень** (детали) | Только список             | После 2.7               |
| **Капча, Cloudflare**    | Нужны прокси и обход      | Позже                   |
| **База данных**          | Только JSON/CSV           | Проект 2.8 (PostgreSQL) |
| **Асинхронность**        | Последовательные запросы  | По необходимости        |
